# 模块1：用户登录注册与个人信息管理

> 课程设计小组项目「校园闲置物品交易小程序」· 成员1（张三）负责模块
> 分支：`feature/zhangsan-auth` ｜ 核心接口：`POST /api/auth/register`、`POST /api/auth/login`
> 技术栈：Node.js + Express + MySQL + JWT（jsonwebtoken）+ bcryptjs

本模块提供：用户注册（注册即登录）、登录（防爆破锁定）、获取/修改个人信息、修改密码，以及供全组复用的 JWT 鉴权中间件。

## 二、后端启动步骤

前置依赖：Node.js v16+、MySQL 8.0

```bash
# 1. 进入后端目录
cd server

# 2. 安装依赖
npm install

# 3. 初始化数据库（会创建 campus_secondhand 库与 users 表）
mysql -u root -p < db/schema.sql

# 4. 配置环境变量：复制 .env.example 为 .env，填写数据库账号密码
#    （Windows: copy .env.example .env；Linux/macOS: cp .env.example .env）

# 5. 启动服务
node app.js
```

启动成功后访问 http://localhost:3000/api/health 返回 `{"code":0,...}` 即正常。

> 前端联调：把 `frontend/common/request.js` 里的 `BASE_URL` 改为电脑局域网 IP（如 `http://192.168.x.x:3000`），HBuilderX 真机运行即可。

## 三、接口文档

> 统一响应格式：成功 `{ "code": 0, "message": "...", "data": {...} }`；失败 `{ "code": 非0, "message": "错误描述", "data": null }`。
> 需要登录的接口，请求头携带 `Authorization: Bearer <token>`（登录/注册返回的 token）。

### 1. 用户注册（注册成功即自动登录）

- **POST** `/api/auth/register`

```json
{ "username": "20230001", "password": "123456", "nickname": "小张", "phone": "13800138000", "email": "test@school.edu.cn" }
```

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| username | 是 | 3-30 位字母、数字或下划线 |
| password | 是 | 6-72 位 |
| nickname | 否 | 不超过 30 字符，不传默认同用户名 |
| phone / email / student_id | 否 | 选填联系方式/学号 |

- 成功响应：**201**

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": {
      "id": 1, "username": "20230001", "nickname": "小张",
      "avatar": null, "phone": "13800138000", "email": "test@school.edu.cn",
      "student_id": null, "created_at": "2026-11-01T13:00:00.000Z", "updated_at": "2026-11-01T13:00:00.000Z"
    }
  }
}
```

- 常见失败：`1001` 参数格式错误、`1002` 用户名已存在

### 2. 用户登录

- **POST** `/api/auth/login`

```json
{ "username": "20230001", "password": "123456" }
```

- 成功响应：**200**，`data = { token, user }`（同注册）
- 常见失败：`1001` 参数缺失、`1003` 用户名或密码错误、`1007` 尝试次数过多已锁定（连续失败 5 次锁 5 分钟）

### 3. 获取当前登录用户信息

- **GET** `/api/auth/me`（需登录）
- 成功响应：**200**，`data = { user }`

### 4. 修改个人信息

- **PUT** `/api/auth/me`（需登录，传哪个字段改哪个）

```json
{ "nickname": "新昵称", "avatar": "https://xxx/avatar.png", "phone": "13900000000", "email": "a@b.com", "student_id": "20230001" }
```

- 成功响应：**200**，`data = { user }`（修改后的完整用户信息）

### 5. 修改密码

- **PUT** `/api/auth/password`（需登录）

```json
{ "oldPassword": "123456", "newPassword": "abc12345" }
```

- 成功响应：**200**，`message: "密码修改成功，请重新登录"`；失败：`1003` 原密码不正确

## 四、错误码表

| code | HTTP 状态 | 含义 |
| ---- | ---- | ---- |
| 0 | 200/201 | 成功 |
| 1001 | 400 | 请求参数格式错误 |
| 1002 | 400 | 用户名已存在 |
| 1003 | 401/404 | 用户名或密码错误 / 原密码不正确 / 用户不存在 |
| 1004 | 401 | 未登录或登录已过期（前端据此自动清登录态并跳登录页） |
| 1005 | 500 | 服务器内部错误 |
| 1006 | 404 | 接口不存在 |
| 1007 | 429 | 登录尝试次数过多，账号暂时锁定 |

## 五、前端对接说明

- `frontend/common/request.js` 已封装：自动携带 `Authorization: Bearer <token>`；响应 `code === 0` 时 resolve `data`，否则 toast 提示 `message`；`code === 1004` 时清除本地登录信息并提示重新登录。
- 登录/注册成功后调用 `setToken(data.token)`、`setUser(data.user)` 即可完成登录态保存。
- 其他组员接口若需要登录态，后端引用 `server/middleware/auth.js` 的 `authRequired`，校验通过后从 `req.userId` 取当前用户 ID。
